# Gagauzium: аудит и предлагаемое расширение словарной базы

## Итог

- Исходная база: **750** записей, ID 1-750.
- Добавлено кандидатов из PDF: **170** записей, ID 751-920.
- Предлагаемый итог: **920** записей.
- Уровни итоговой базы: beginner — **601**, conversational — **319**.
- Найдено групп возможных дублей/вариантов: **30**.
- Подготовлено предлагаемых изменений существующих значений: **20** (12 high, 8 medium).

Исходный `words_data.json` не изменялся. Все предлагаемые исправления существующих записей находятся только в `proposed_changes_existing_words.json`.

## Проверка исходной базы

- Все 750 ID уникальны, последовательны и не перенумерованы.
- Обязательные поля присутствуют; категории совпадают с `category_metadata.py`.
- Поле `learned` в контентной базе остаётся `false`.
- PDF содержит текстовый слой; OCR не потребовался.
- Автоматическая сверка существующих записей: source_verified — 450, needs_review — 184, not_found_in_source — 116.

`not_found_in_source` не означает автоматически ошибку: причина может быть в переносе статьи, варианте написания или составной записи.

## Новые слова

Каждое из 170 новых слов:

- найдено как русско-гагаузская словарная статья в `slova_1-5_kl.pdf`;
- имеет `pdf_page`, `printed_page` и полный `source_entry` в рабочем Excel-каталоге;
- проверено на точные совпадения с отдельными записями и вариантами через `/`;
- получило последовательный ID после 750;
- получило `level` и массив `part_of_speech`;
- имеет `learned: false`;
- помечено `romanian_needs_review`, поскольку румынская часть отсутствует в PDF.

Первоначально планировалось 217 новых слов. Фактически выбрано 170: остальные кандидаты отсутствовали в PDF, имели неполную/неоднозначную статью, пересекались с существующей формой или были недостаточно полезны для текущего объёма. Итоговые 920 записей находятся в целевом диапазоне 900-1050.

## Записи, требующие ручной проверки

Приоритетные примеры находятся в листе `Review Queue` итогового Excel-файла и в `proposed_changes_existing_words.json`. Особенно важны:

- ID 59: `kız` в PDF соответствует «девушка; девочка», а не подтверждённому значению «дочь»;
- ID 253: для «начальник» PDF даёт `zaabit / başkan`, текущий `bakan` не подтверждён;
- ID 329: для «слушать» PDF даёт `seslemää`, а `işitmää` уже означает «слышать»;
- ID 446: для «терять» PDF даёт `kaybetmää`; возможен будущий дубль с ID 445;
- ID 667: текущая форма `açıklamak` не совпадает с оформлением статьи; предложен подтверждённый вариант `annatmaa`.

Ни одно из этих изменений не применено автоматически к `proposed_words_data.json`.

## Возможные категории

Предложения по перемещению существующих записей также не применены автоматически. Например, кухонные предметы из `Дом и Предметы`, школа из `Город и Транспорт`, здоровье из `Базовые` и торговые объекты из городской категории отмечены в Excel как `suggested_category`.

## Ограничения

- База не проверена носителем гагаузского языка.
- `source_verified` означает совпадение с приложенным PDF, а не человеческую лингвистическую верификацию.
- Румынские переводы новых слов созданы моделью и требуют отдельной проверки.
- Автоматический разбор PDF может пропускать сложные переносы и многозначные статьи.
- Для слов с несколькими переводами выбран учебно-практичный подтверждённый вариант; полная исходная статья сохранена в Excel.

## Замечание по приложению

`main.py` пока не фильтрует слова по полю `level`: интерфейс показывает beginner как активный уровень, а остальные уровни — как статические заблокированные элементы. После утверждения каталога потребуется отдельное изменение логики приложения, чтобы `conversational` реально использовался.
